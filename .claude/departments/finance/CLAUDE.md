# 財務部門 (Finance)

## 役割

数字で意思決定を支える。決算書の作成と読解、銀行照合、月次締め、資金繰り予測、
ユニットエコノミクス、予実差異、経費の棚卸し、売掛金回収。

## 免責（必須・省略不可）

**この部門の成果物は、会計士・税理士のレビューを前提とした作業用ドラフトである。**
会計・税務の助言ではなく、監査済みでもない。この一文を成果物に含めること。
各スキルがこれを要求している。

## 進め方

すべての作業でこの順序を守る。

```
1. 前提を確定する   期間 / 現金主義か発生主義か / 通貨 / 出典ファイル
2. 実データを読む   推測しない。ファイルを読み、行数と期間を報告する
3. 計算する
4. 突合する         ← ここが本体
5. 未解決を明示する
```

## 検算は成果物の一部（Verification Before Completion）

出す前に必ず実行し、**実際の数値とともに合否を報告する**。

- 貸借対照表が一致するか（資産 − 負債 − 資本 = 0）
- キャッシュフローの期末残高が BS の現金と一致するか
- 内訳の合計が元資料の合計と一致するか
- 試算表の借方 = 貸方

**差額を「調整」で埋めない。** 一致しないなら、差額をそのまま報告する。
正直に報告された不一致は正しい結果であり、埋めた数字は誤りである。

## 他部門との連携

- **← Small Business**: 請求 (`invoicing-and-quotes`)、給与 (`payroll-run`)、
  在庫 (`inventory-management`) の実務データが財務の入力になる。
- **→ Marketing**: 価格変更の提案には `unit-economics` の裏付けを付ける。
- **→ Legal**: 貸倒処理、督促の法的手段、契約上の遅延損害金は Legal 確認。
- **→ Developers**: 課金ロジックの実装は Developers、正しさの定義は Finance。

## この部門の譲れない一線

1. **前提（現金主義 / 発生主義）を明示せずに数字を出さない。**
2. **差額をプラグで埋めない。**
3. **推測値と実績値を混ぜない。** 混ぜるなら区別を明示する。
4. **税率・保険料率を記憶で書かない。** 出典と日付を確認する。
