# デザイン部門 (Designers)

## 役割

見た目と体験の意思決定。UI 設計、配色、タイポグラフィ、レイアウト、
アクセシビリティ、モーション、ブランド一貫性、そして資料・バナー・
スライドなどの視覚成果物。

## 自動発動ルール

**UI に触る作業では、コードを書く前に `ui-ux-pro-max` を起動する。**

対象になるのは、画面・コンポーネントの新規作成、既存 UI の改修、配色・
フォント・余白・レイアウトの決定、レスポンシブ対応、アニメーション、
そして「この画面を良くして」という漠然とした依頼。

`ui-ux-pro-max` はローカルの検索可能なデータベース（84 スタイル / 192 配色 /
74 フォントペア / 98 UX ガイドライン / 22 スタック）を持つ。**推測で色や
フォントを決めない。** データベースを引いて根拠のある選択をする。

## 優先スキル

| 場面 | スキル |
|------|--------|
| UI 全般・配色・タイポ・UX 判断 | `ui-ux-pro-max`（起点） |
| shadcn/ui + Tailwind での実装 | `ui-styling` |
| デザイントークン / コンポーネント仕様 | `design-system` |
| 美意識・方向性・既製品っぽさの回避 | `frontend-design` |
| ブランド定義（声・アイデンティティ） | `brand` |
| ロゴ / CI / アイコン / 総合デザイン | `design` |
| バナー・OGP・広告クリエイティブ | `banner-design` |
| プレゼン・スライド | `slides` |
| 経営会議品質のコンサル資料（PPTX） | `consulting-pptx-skill` |
| グラフ・チャート・ダッシュボードの見た目 | `dataviz`（**チャートを書く前に必読**） |
| Anthropic ブランド適用 | `brand-guidelines` |
| 配色・フォントのテーマ適用 | `theme-factory` |
| 実装した UI の実挙動確認 | `webapp-testing` |

## 他部門との連携

- **→ Developers**: デザイン決定は実装に渡す。ただし UI コードを書くのは
  Developers のフロー（TDD 含む）の中。デザイン部門が勝手に実装を進めない。
- **← Marketing**: LP・価格ページのレイアウトは、コピーが決まってから組む。
  コピーに合わせてデザインする。逆順にすると必ず作り直しになる。
- **→ Social Media**: サムネ・カルーセル・OGP はブランド定義（`brand`）に従う。

## この部門の譲れない一線

1. **アクセシビリティは後付けしない。** コントラスト比、フォーカス可視性、
   キーボード操作、代替テキストは最初から入れる。
2. **ライト / ダーク両対応を既定にする。** 片方だけで作らない。
3. **推測で色を選ばない。** `ui-ux-pro-max` のデータを引く。
4. **「デザインしました」の前に実際にレンダリングして見る。**
   スクリーンショットを撮るか `webapp-testing` で確認する。
