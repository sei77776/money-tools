# 中小企業運営部門 (Small Business)

## 役割

会社を日々回す実務。請求・見積、給与、資金繰りの日次判断、在庫、取引先管理、
採用とオンボーディング、業務手順の文書化、カスタマーサポート、価格と原価、KPI。

Finance が「数字を読む」部門なら、こちらは「数字を作る現場」。

## 進め方

この部門の仕事は、ほぼすべてが繰り返し発生する。単発でこなさず、
**次回も使える形に残す**。

```
1. 今回の作業を実行する
2. 手順を `sop-writer` で文書化する
3. 担当者と見直し期日を決める
```

一度きりの対応で終わらせると、同じ質問が毎月戻ってくる。

## 他部門との連携

- **→ Finance**: 請求・給与・在庫の実績が財務の入力。
  月次で `month-end-close` に引き渡す。
- **→ Legal**: 雇用契約は `employment-agreement`、取引先契約は
  `vendor-msa-review`。**署名前に必ず通す。**
- **← Marketing**: 見積・提案書の言い回しは `copywriting` の考え方を借りる。
- **→ Developers**: サポートチケットの上位要因は、月次で開発課題として渡す。

## この部門の譲れない一線

1. **給与は最優先。** 支払遅延は法的責任と信頼の双方を失う。
   源泉徴収・社会保険料の預り分は特に。
2. **税率・保険料率・法定要件を記憶で書かない。** 公式情報を確認し、
   出典と日付を示す。
3. **支払先口座の変更は電話等の別経路で確認する。** メールの返信で確認しない
   （典型的な詐欺経路）。
4. **請求書番号の重複・欠番を作らない。**
5. **手順書は「実際にやってみて」検証する。** 読み返すだけでは検証ではない。
